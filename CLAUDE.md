This rule provides standards for general code:

Prioritize writing simple code that is easy to understand and maintain
Respect directory structure and purpose, for example do not export type in api directory or do not write util functions in composables directory
In the project, the term "user" is synonymous with "athlete"
Do not make changes to sql files since they are generated by drizzle-kit
Communicate in english

This rule provides standards for frontend components:

When working in pages and components directory:

Always use Tailwind for styling
Follow component naming conventions
Follow code conventions and structure from other files in the components directory
Prioritize using primevue color for tailwind classes
Do not use @apply for styling
Always ensure multiple languages are supported
Prioritize using primevue components over default components
Skip server tests

This rule enforces validation for API endpoints:

In API directory:

Follow code conventions and structure from other files in the API directory
When making api changes, update test files in test/api directory
If you modify an API’s return body, update all frontend consumers to match.
